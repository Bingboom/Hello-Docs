# 小野露营市集：本地海报自动更新案例

这是供 AI 知识分享使用的教学小系统。三款产品、全部参数、价格和 Q 版插画均为虚构内容，不可作为真实产品规格或销售资料。

## 先看什么

双击 [index.html](index.html) 查看三张成品和素材索引，无需安装运行环境。交互演示必须启动本地程序。

三张 A5 PDF 都由 XeLaTeX 编译，分别采用大图主视觉、图文分栏、参数卡片排版；共享色彩、字体、字号层级及组件样式。PNG 只是从 PDF 渲染的预览，不是独立排版的替代品。

## 启动交互演示

需要 Python 3.10+、XeLaTeX（TeX Live / MacTeX）、Poppler 的 `pdfinfo` / `pdftoppm` / `pdftotext`。不需要 Python 第三方库，也不需要钉钉账号。

本次实际运行环境为 macOS；程序使用 Unix 文件锁，Windows 原生 Python 不适用，可考虑 WSL，但未在该环境验收。跨机器还需安装主题中指定的中英文字体，不把本机通过视为所有环境都通过。

在本目录执行：

```sh
python3 demo.py serve --port 8765
```

macOS 也可双击 `启动本地演示.command`。看到地址后，在浏览器打开 `http://127.0.0.1:8765`。窗口需保持运行；Ctrl+C 停止。本例没有设置开机自启、系统计划任务或云端监控。

如果 8765 端口已被占用，先核实是否本演示已经运行；也可换用 `--port 8766`。首次生成三张通常需要几十秒，以实际机器为准。

## 三分钟操作

1. 看产品表和内容表：`products.csv` 保存参数、价格和版式，`content.csv` 保存带 `{{变量}}` 的介绍文案；两表以 `model_id` 关联。
2. 看三张 PDF：图片、文字、参数与价格相同职责的组件共享样式，但布局不同。
3. 只改小野 500 的教学价并保存。保存动作只写 CSV，独立后台每两秒检测变化并调用 XeLaTeX。
4. 等待这一行显示新版本，打开 PDF 确认价格；对照另外两款的版本和文件 SHA，确认它们没有更新。
5. 查看“本地回写表”和运行记录：更新时间、版本、摘要和 PDF SHA 都来自真实程序执行。

交付时的小野 500 已是 899，因为验收实际执行了 999 → 899。再次演示可先改回 999，等更新完成，再改为 899。版本继续递增，不清除历史。

## 文件分工

| 文件 | 负责什么 |
| --- | --- |
| `data/products.csv` | 输入事实、记录 ID、资产文件名、版式选择 |
| `data/content.csv` | 标题、带变量的介绍文案、使用场景 |
| `assets/*.png` | 固定 Q 版插画；修改参数时不重新生成图片 |
| `latex/theme.tex` | 统一字体、颜色、字号辅助函数、基础画布参数 |
| `latex/components.tex` | 标题、介绍、插画、指标、参数卡、价格和页脚组件 |
| `latex/layout_*.tex` | 三种不同的页面结构和位置，不重复定义主题样式 |
| `latex/poster.tex` | 共用页面入口，加载本次选定的版式 |
| `demo.py` | 查表、校验、变量替换、编译、变更检测、版本记录、本地 HTTP 界面 |
| `output/pdf` | 当前三张 PDF，生成成功后原子替换 |
| `output/history` | 历史 PDF、输入快照、LaTeX 源文件和真实编译日志 |
| `output/records.csv` | 输出状态表，不作为输入，不引发循环更新 |
| `output/events.jsonl` | 真实运行事件；包括开发中的失败，不伪造成功 |
| `deliverables` | 本次验收冻结的三张 PDF 与预览，便于离线分享 |
| `evidence` | 本次真实截图、验收基线与报告 |

## 借鉴 Auto-Manual 的地方

借鉴工程仓库 `docs/renderers/contracts/STYLE_DEFINITION.md` §0.1、§8.2、附录 A 的分层方式：内容、主题、组件和版式分开。没有复制说明书的视觉样式，也没有接入正式说明书生产链。这里是独立教学样例，不宣称复用了完整 Auto-Manual 构建器。

每条记录选择 `hero`、`split` 或 `cards`。布局文件只组合组件；组件统一消费主题颜色和字体。修改共享样式影响全部海报，修改某个布局只影响使用该布局的记录。

## 更新与失败边界

- 输入摘要包含该条数据、引用的内容、插画、公共主题/组件、选定版式和构建程序。输出状态与更新时间不参与输入摘要。
- 同一份数据未变化且 PDF 校验一致时跳过构建。外部编辑 CSV 的内容和价格变化也会触发检测。
- 未知变量、重复型号/记录 ID、非法数字、缺图、缺字、溢出或编译失败会报错；不以空值或零替代。
- 失败不覆盖上一份成功 PDF，也不增加成功版本。相同失败输入 30 秒后允许重试。
- 编译时数据再次变化，旧快照不会发布，等待下一轮处理。
- 数据应保留示例的字段结构。输入表删行不会自动删除历史文件，演示不提供批量删除操作。
- 服务只监听 `127.0.0.1`，包含 Host 和写请求令牌检查；不应直接暴露公网。
- 自动更新仅在服务运行、电脑唤醒时有效。钉钉读取、上传、回写、长期无人值守均是后续接入，不属于本次本地验收。

## 验证

```sh
python3 -m unittest -v test_demo
python3 demo.py build
```

行为测试使用临时目录与测试编译器；真实 PDF 编译和浏览器改价另由 `evidence/acceptance.json` 取证，二者不能互相替代。验收截图中的版本号包含早期原型迭代，不从 1 重新编号。

`verify_acceptance.py before` 保存新验收基线；它拒绝覆盖现有基线。随后通过浏览器改价，再执行 `python3 verify_acceptance.py verify` 核实只更新目标记录。再次验收请保留旧 evidence 并使用独立副本。

`seed-data.mjs` 仅用于制备初始教学 CSV，依赖 Codex 的 Artifact Tool；普通用户运行本例无需执行它。`assets/provenance.json` 保存内置图像生成工具的原始提示词。

维护分享材料时，在安装 Pandoc 的环境运行 `python3 render_materials.py`，从 Markdown 更新主稿和四个素材页面，再执行 `python3 validate_materials.py` 检查同文和链接。`python3 package_materials.py` 只冻结与验收哈希一致的成品并打包，排除运行目录、旧原型截图和私有钉钉绑定。

## 钉钉当前状态

用户确认图片可入表后，已把三张最终海报 PNG 一次性上传到教学表的对应型号行，并回读核验附件及文件哈希。三份 PDF 也已上传到对应型号行并回读确认。成功版本、成功更新时间仍未自动回写。此操作由工具执行，未接入 demo.py 的后台，后续本地改价不会自动更新钉钉预览。
