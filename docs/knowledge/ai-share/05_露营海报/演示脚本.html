从一张海报到一个小工具：现场演示脚本

建议用 12–15 分钟，顺序与主稿一致：先讲工作，再看怎么做，接着演示改价与交付，最后留一个小练习。鹈鹕放在文末作可选彩蛋。全部产品和价格均为教学虚构。

演示前：准备工作台

使用 HTML 工作台下载包，按 工作台使用说明 检查环境并启动。页面地址为 http://127.0.0.1:62100/workbench。

提前打开三款 HTML、PDF 和 PNG。小野 500 若已是 899，先在页面改回 999，等所有输出成功，记录三款当前版本与更新时间；不要清理历史或手改版本号。静态截图用于备用，不能说成正在运行的页面。

先讲任务：周五下午的一条消息（1 分钟）

“明天露营市集，三款产品各做一张海报，风格统一，但别长得一模一样。小林手里有资料和插画，先要把这件事做出来。”

展示主稿第一节的三张海报。先看出三种布局，再指出共用的色彩、字体和参数样式。此处展示的是改价前的成品，小野 500 为 999。

回到起点：一个空文件夹，一张海报（2 分钟）

跟着主稿第二节，打开 完整练习第 1 步，展示第一条需求和真实结果。

“先给完整资料，只做一张。看看数字对不对、图片对不对、文字有没有挤出去，再提下一次修改。我们熟悉业务，就能判断哪里不对，不需要先读懂全部代码。”

再展示另外两张：“共享风格，不是复制排版。300 用大图，500 做分栏，1000 做参数卡片。”

需要解释资料复用时，打开 两张资料表的预览。说明这份静态记录的小野 500 为 999；运行中的工作台读取下载包内的本地 CSV，不是实时读取钉钉。表格按型号关联，变量把这一款的资料填进句子。

改一次价：保存后停手（3 分钟）

跟着主稿第三节：

“海报做好了，负责人又发消息：小野 500 改成 899，另外两款不动。”

在运行的工作台里把 999 改成 899，点保存后停止操作，不再向 Agent 发送生成指令。等更新成功，分别打开这款的新 HTML、PDF 和 PNG，核对 899；再查看另外两款的价格、版本和更新时间没有变化。

“第一次，我们让 AI 帮忙把做法写成程序。以后改价格，程序就按已经确定的规则更新文件，不用每次重新描述需求。今天留下来的，不只是三张海报，还有下次可以继续用的办法。”

强调：保存成功不等于导出成功。页面变了但 PDF 还是旧价格，不能算完成。现有结果与核验边界 供会后查看。

留住能用的一版，再交给同事（2 分钟）

展示工作台里的版本与变更记录：“程序告诉我们这次改了哪一款、是否成功；生成失败要保留上一份成功文件。”

再说明 Git 的用途：“确认工具能用时，在本地保存一个版本。GitHub 是后续同步和协作的地方，不是做出第一张海报的前置条件。”

打开主稿第三节的钉钉教学表和原始实录：“确认过的 PNG、PDF 按型号放回对应产品行，上传后还要重新读取、打开附件检查。”

已经记录的是一次上传，不是持续同步。现场不修改共享教学表；需要演示上传时，用单独授权的测试表。明确说明：在钉钉改价自动生成并替换附件，尚未接通。

往前走，但今天先做一小步（2 分钟）

跟着主稿第四节，提三个下一步：批量活动物料、手机产品展示页、反馈整理。这些是延伸方向，不是已有功能。

“第一次不必把整套系统做完。先用提供的资料做出一张海报，再改一个标题，打开检查。能走通这一圈，今天就成功了。”

指向完整练习第 1 步；下载包用于先体验成品，不代替学习制作过程。请大家想一件自己反复在做的工作，下一次再试着把它留下来。

可选彩蛋：会骑车的鹈鹕（1–2 分钟）

时间允许再打开主稿文末的动画，展示原提示词：“生成鹈鹕骑车的 HTML”。暂停、调速、按铃，观察脚与踏板怎样配合。

“这是一个开放式作品。工作工具也是一样：要打开、操作、核对，不能只听 Agent 说已经完成。”

“只改围巾颜色，其他不动”可留作观众练习，不冒充现场已经执行。没有多模型实测排名，不用这个作品证明模型在所有任务上都更强。

现场故障预案

  • 服务未启动：按使用说明启动，确认地址与状态。网页中的静态实录不是工作台。
  • 缺 Python、Node.js、浏览器或依赖：说明环境尚未就绪；时间不够就展示已留存的结果，不宣称现场跑通。
  • 导出慢或失败：看真实错误，等成功再打开文件；不要只凭价格框变化宣布成功。
  • 端口冲突：先核实是否已有该工作台运行，不随意结束其他程序。
  • 钉钉打不开：展示真实上传实录，说明当前网络或权限问题。本地主线不依赖钉钉连接。
  • 用完回到服务终端按 Control-C；不要留下后台服务却让听众以为已经关闭。
