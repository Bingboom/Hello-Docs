# 阅读统计维护说明

主稿与引用资料页使用 Umami Cloud。`reading-analytics.js` 保存公开网站 ID，由 `render_materials.py` 统一注入页面，不要逐页粘贴统计代码。跳转页和内嵌动画不注入。

## 后台查看

登录 Umami，打开对应网站，选择日期范围。页面浏览量、访客数与来源在网站概览查看；以 `/ai-share/` 路径筛选分享资料。

自定义事件：

| 事件 | 属性 | 含义 |
| --- | --- | --- |
| `reading_progress` | `page`、`percent` | 正文可见位置达到 25、50、75、100%，每页每档一次 |
| `reference_click` | `page`、`target` | 点击 GitHub 练习、参考资料或露营案例 HTML 链接 |
| `download_click` | `page`、`target` | 点击资料下载链接（ZIP、PDF、图片、CSV 等） |

进度不是读懂或读完的证明；快速滚动、目录跳转也可能达到相应位置。下载点击不证明文件下载完成。访客数按 Umami 去重口径估算，不是准确人数；拦截器和隐私设置可能导致漏计。分享应用也可能不提供来源，显示为直接访问。

## 数据边界

只在 HTTPS 的 `ht-doc.readthedocs.io` 顶层页面加载；本地预览和离线包不加载远程统计。尊重 Do Not Track 和 Global Privacy Control，不开启录屏、热图、身份绑定或表单采集。页面 URL、点击目标不包含查询参数和片段；来源仅保留站点 origin。Umami 服务会接收到访问请求并按其隐私政策处理，不能将统计称为“完全不接触用户数据”。

## 检查与发布

运行 `node --test docs/knowledge/ai-share/05_露营海报/test_reading_analytics.cjs`，随后运行同目录的 `render_materials.py` 和 `validate_materials.py`。再次生成不应产生额外差异。

上线后需在真实浏览器打开主稿、滚动、点击引用稿和下载链接，检查 Umami 请求成功及后台事件入库。自动测试使用模拟发送，不污染正式统计，也不能替代上线验收。尚未上线时不能宣称已有数据；历史访问无法补采。
