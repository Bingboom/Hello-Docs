一、用代码解决工作中的问题

周五下午，小林接到一个任务：给周末的露营市集做三张产品海报。资料已经有了，但名称、介绍、参数和价格散在表格里。负责人又补了一句：“活动价可能还会改。”

如果只做这一次，逐张排版也能完成。可下次换产品、改价格，还要重复取数、改字、检查。小林想：能不能把这些重复步骤交给一个小工具？

他不需要一开始就知道程序怎么写，先把手头的资料、想要的结果和不能出错的地方讲清楚。Agent 负责实现，小林负责看结果、提修改要求。

今天就跟着小林做这件事。每次先看一个结果，再理解它背后的做法，最后试一个小改动。不要求记住所有命令。

先想一下： 你的工作里，哪件事总是“换一份资料，再做一遍”？先选一个具体动作，不急着设计完整系统。

二、从需求到实现

先看小林想得到什么：三张带 Q 版插画、介绍、参数和价格的海报。它们看起来属于同一个系列，但排版不同，既能打印，也能发给同事。

这是本案例实际生成的预览：三份 A5 单页 PDF，分别使用大图、图文分栏和参数卡片排版。PDF 用 LaTeX 制作；插画是生成素材，文字和参数另行排版，不画死在图片里。

“小野 300 / 500 / 1000”及其参数、价格、插画均为教学虚构资料，不是真实销售资料。

打开三款成品和案例素材

怎样开始

小林用已经安装并登录的 Codex 或 Claude Code 打开一个空文件夹，把资料交给 Agent，先提一个小要求：

对 Agent 说：

帮我做一张小野 300 的产品海报，放上介绍、参数、价格和这张插画，PDF 用 LaTeX 制作。先把预览打开给我看。资料缺了就问我，不要猜，也先不要上传钉钉。

先做一张，是为了尽早看见结果：参数是否对应、字是否清楚、插画是否放对。第一张确认后，再增加另外两款。

讲一点：资料为什么要整理成表？

小林不想每次都重新交代一遍产品资料，所以把它们整理成两张表：产品表放参数和价格，内容表放介绍。两张表用同一个型号对应起来。本地保存成 CSV——一种简单的表格文件。

打开钉钉多维表：产品与海报

这是整理后放到钉钉的教学表；开始做本地工具时，还不需要连接钉钉。

比如产品表里写“小野 500，512 Wh”，介绍模板里写：

{{product_name}} 的 {{capacity_wh}} Wh 教学容量

程序按型号找到对应资料，填好后就变成：

小野 500 的 512 Wh 教学容量

大括号里的部分是变量标记：位置固定，内容从资料中取，不由 AI 临时猜。先核对这一句，理解后再看整个流程：

你也试一下： 让 Agent 在测试副本里改一项容量，再生成一句介绍。看数字是否跟着变化，产品名是否仍然对应。这里先手动要求生成，不代表已经实现自动更新。

想看看变量怎样写成代码，可以打开 the craft of selfteaching：一句产品介绍的小练习。本例模板标记与 Python 写法不同，引用稿里有对照说明。

三、修改与调试

第一张能看了，小林才发现：“三张都用一个版式，摆在一起有点单调。”

对 Agent 说：

小野 300 保留大图；500 改成图片在左、参数在右；1000 改成下面三张参数卡片。三张只共享颜色、字体和组件样式，布局要不同，不要修改产品数据。

看结果： 打开 三款海报，先看排版是否不同，再看数字有没有被一起改掉。小野 500 应仍是 512 Wh、500 W、5.2 kg，每份 PDF 都应只有一页。

讲一点：共享样式，不等于共享排版。

可以把颜色、字体和价格条的样式理解成一套公共零件。三张海报用同一套零件，却可以摆在不同位置。以后要换品牌色，就修改公共样式；只想调整小野 500 的图文位置，就改它的布局。

小林不必先学会所有文件的写法。对着成品，他可以继续问：

为什么修改 500 的分栏，不会把另外两张也改掉？请指出对应文件，只讲这一次改动涉及的部分。

你也试一下： 只把一张海报的介绍字号调大，其他内容不变。打开结果，看看有没有溢出、截断。不好看就截下问题，告诉 Agent 哪里不对，让它继续改。

这就是调试：提出一个改动，运行，看结果，再定位问题。本次制作也遇到过字体不可用导致编译失败，修正配置后才生成成功。出错并不奇怪，重要的是能展示问题和修正后的结果。

想看代码怎样配合 · 需要时再查文件分工和运行说明

四、复用与维护

海报做完，负责人通知：“小野 500 从 999 改成 899，另外两款不动。”

小林这次想省掉反复发“重新生成”的步骤。

对 Agent 说：

让我在本地页面改价格。保存后，工具自己发现变化，只更新受影响的海报。告诉我哪款更新成功、最近改了什么；失败时保留上一次成功的文件。

实际结果：

产品 修改前价格 修改后价格 海报结果
小野 300 599 元 599 元 文件不变
小野 500 999 元 899 元 新 PDF 显示 899
小野 1000 1599 元 1599 元 文件不变

改价前 · 保存后 · 自动更新完成

上面是已有演示的真实截图，文件核验见 验收记录。

讲一点：保存数据，不等于海报已经更新。

背后还需要程序持续检查变化、重新生成文件，再记录结果。所以不能只看到网页上的价格变了，就认为完成了；还要打开新 PDF，核对另外两张是否不受影响。

你也试一下： 在本地工作台只改小野 500 的价格，保存后不要再发生成指令。等状态显示成功，再打开 PDF。素材包已经是 899；复现这次演示时，先改回 999 并等生成成功，再改到 899。

目前自动更新只在本地服务运行、电脑唤醒时有效。钉钉端的持续触发和附件自动更新尚未实现。

下次换一批产品时，整理好的表格格式、样式和代码还可以复用。小林只需交代变化的部分，再做同样的核对，不必重新描述整个工具。

资料和要求怎样留给下次用

五、GitHub：借鉴项目与版本管理

工具能用了，小林有两个新问题：“不懂的地方去哪儿学？”“改坏了怎么找回上一版？”

先借鉴一个小做法。

GitHub 上既有可运行的项目，也有学习资料。例如 the craft of selfteaching，可以从目录里找到“字符串”，结合刚才的变量练习读一小节，再运行和修改代码。

它是学习资料，不是现成的海报生成器。露营海报的数据、样式、组件和布局分开维护，则借鉴了 Auto-Manual 的组织方式，没有照搬说明书的外观或接入正式生产链。借鉴前要看清项目用途和许可。

你也试一下： 打开 一句产品介绍的小练习，先运行一次，再只改价格。不懂的地方，让 Agent 结合这次输出解释，不急着把整本书看完。

再留下一份可用版本。

小林确认三张海报都能生成后，可以用 Git 保存一个版本。改动后再看差异，知道哪些文件变了，也方便找回修改前的内容。GitHub Desktop 提供图形界面，不必先背命令。

对 Agent 说：

帮我查看这次改动，确认没有把账号信息或临时文件放进去。先展示差异，等我确认后再保存一个版本，说明这次做成了什么。

Git 在本机记录版本；需要多台电脑同步或与人协作时，再推送到 GitHub。保存本地版本和上传到远端，是两件事。

六、让 Agent 调用更多工具：CLI 与 MCP

最后，小林想让同事在钉钉的产品表里直接拿到海报。此前 Agent 已经能操作本地文件，现在还要连接工作软件。

先看两个具体动作，再认识它们的名字。

CLI：通过命令调用工具

对 Agent 说：

把本地海报工作台启动起来，打开页面给我看，再告诉我用完怎么关闭。

有终端访问能力的 Agent，可以调用现成程序来完成这件事。这类通过命令调用工具的方式，叫 CLI（命令行接口）。

看结果： 页面真的打开、产品资料能显示、海报能查看。运行命令本身不是完成标志。

检查文件改动也一样：GitHub Desktop 可以点开看，Agent 也可以运行 git status。使用的是同一个工具的不同入口。具体启动命令放在 运行说明，需要时再查。

MCP：连接工具和资料

对 Agent 说：

把三款最终海报的 PNG 和 PDF，按型号放到教学表对应行。不要覆盖其他字段。完成后重新读取这三行，检查型号与附件是否对应。

接好钉钉 MCP 后，Agent 可以调用服务提供的读表、写表或上传功能，在账号权限和工具支持范围内完成操作。小林提供目标位置与要求，不需要先找到字段 ID、记录 ID。

实际结果： 本案例已建立三条虚构产品记录，上传三张 PNG 和三份 PDF，并回读核对。打开 教学表，就能从对应产品行查找附件。

你也核对一下： 点开小野 500 的附件，看产品名和价格是否正确，再检查另外两款。后续要自己练习，先复制成测试表，不在这张教学表里随意改数据。

CLI 和 MCP 都能让 Agent 使用已有工具：前者常通过命令调用，后者按服务约定连接工具与资料；一个任务可以同时用到两者。

小林下一步还想“钉钉改了资料，海报和附件也自己更新”。这仍需持续运行的服务或触发机制，以及失败处理。接好 MCP、完成一次上传，不等于开启了自动化。 目前钉钉端的成功版本、成功时间也尚未接入自动回写。

附录：跟着小林，从空文件夹做出一个海报工具

准备一台电脑、已登录的 Codex 或 Claude Code，以及一个空文件夹。下面涉及的产品资料仅用于教学；需要安装软件时，先让 Agent 解释用途，再确认。

1. 打开空文件夹

对 Agent 说：

我不懂编程，想做一个露营产品海报工具。请带我一步步做，每次只告诉我当前需要做什么。由你创建文件和代码、检查环境；安装软件先问我。先做出一张海报，不要一开始做完整系统。

看到这些再继续： Agent 确认文件夹位置、说明下一步要提供哪些资料。看不懂就问“我现在需要点哪里？”

2. 提供资料，先核对表格

产品 容量 输出 重量 教学价 介绍场景
小野 300 288 Wh 300 W 3.6 kg 599 元 轻装出游
小野 500 512 Wh 500 W 5.2 kg 999 元 周末露营
小野 1000 1024 Wh 1000 W 9.8 kg 1599 元 多人营地

对 Agent 说：

把这些教学虚构资料整理成表格保存，为每款写一句介绍。涉及容量、重量等参数时，从表格取值，不要编。展示整理结果；以后参数改了，生成的介绍也要使用新值。

看到这些再继续： 三款资料没有漏，数字正确，介绍与型号对应。资料如何保存、变量如何替换，让 Agent 实现。

3. 先做一张，再扩展成三张

先提供自己的产品图，或对有图片生成功能的工具说：

画一张露营便携电源的 Q 版插画，森林绿配奶油色，圆润可爱，不要文字、参数和价格。先做小野 300，确认后再做同系列的另外两款。

再对 Agent 说：

用参数、介绍和插画做小野 300 的 A5 单页海报，PDF 用 LaTeX 制作。打开真实预览给我看，文字和价格以后要能修改。

第一张看过后再说：

再做另外两款。三张共享颜色、字体和组件样式，但分别用大图、图文分栏和参数卡片排版。

看到这些再继续： 三份 PDF 都能打开，每份一页，没有缺字或截断，数字正确。画得好看不代表数据正确，两者分开检查。

4. 做页面，测试自动更新

对 Agent 说：

做一个本地页面，让我看资料、改价格、查看海报。保存后程序自己发现变化，只更新受影响的海报，不用我再说“重新生成”。请启动并打开页面，告诉我下次怎么打开、用完怎么关闭。

亲自做一次： 把小野 500 从 999 改成 899，保存后等待。打开新 PDF 确认 899，再看另外两款是否未变。

如果不一致，把现象告诉 Agent，让它排查后陪你重新测试，不接受只修改预览文字。

5. 让工具说明状态，并保留好文件

对 Agent 说：

告诉我每款最近什么时候更新、改了什么、有没有成功。资料缺失或填错要提示，不要猜；生成失败时保留上一份成功海报。请在测试副本里验证这些情况。

看到这些再继续： Agent 展示失败提示和测试结果，旧海报还能打开，失败没有被记成成功。最后让它留下“怎么打开、换资料、换图、检查和排错”的简短说明。

6. 本地确认后，再放到钉钉

先按 连接说明 配好 MCP，不要把密码贴进对话。提供自己有权限的测试空间链接，然后说：

在这个空间为教学产品建立“产品与海报”多维表，放入三款参数、介绍，以及对应图片和 PDF。已有表先核对，不重复建表，不修改其他资料。完成后给我链接，回读检查每一行。

亲自做一次： 在表格里逐行点开图片和 PDF，核对型号。真实操作截图就在实际页面截取，不用生成图代替。

如果还想做钉钉自动更新，另提下一步需求：

请先说明钉钉数据变化后自动生成、上传新海报，需要哪些权限和持续运行条件。我确认后再做；失败时保留旧附件。

这一步是后续扩展，本案例尚未跑通。验收时必须实际改一款数据，确认文件和附件自行更新，不能用一次人工上传代替。
