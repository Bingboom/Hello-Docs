一、用代码解决工作中的问题

工作中，有些需求很具体，现成的软件却未必刚好合用。比如想把分散的资料放在一起查，按自己的规则批量处理文件，或者做一个符合自己使用习惯的页面。借助 Agent，我们可以尝试用代码把这些想法实现出来。

二、从需求到实现

以学生情况卡为例：把成绩、课堂表现和家访记录放到一起，按学生查看、搜索，并打印成每人一页的材料。

这个例子用网页呈现。批量处理文件、核对表格，也可以直接写成脚本运行。

怎样开始

用已经安装并登录的 Codex 或 Claude Code 打开一个项目文件夹，把要用的资料放进去就可以开始。文件内容先保持原样，让 Agent 阅读和整理。

接着，把要做的事告诉它：

帮我做一个在电脑上使用的学生情况卡工具。根据这些成绩、课堂表现和家访记录，按学生生成情况卡，每人一页，方便打印。缺少的记录标出来。做好后告诉我怎么打开、怎么换资料。

先说清手头有哪些资料、最后想做成什么样，不用急着决定用什么技术。下面准备了完整需求和样例资料，可以直接复制给 Agent 试一试。

跟着做一次：完整需求、样例资料和检查方法

做完后，按照 Agent 的说明打开结果。看看分数有没有算对、资料有没有放错人、打印有没有截断。打不开就把现象或截图发给它，让它继续检查。

三、修改与调试

页面能用后，试着加一个功能：

加一个搜索框，输入姓名或学号，就能找到对应学生的情况卡。

做好后，搜一下“张三”和“S002”，看看是否找对了人。还可以接着问 Agent：“搜索功能加在哪个文件里？哪段代码负责筛选学生？结合刚才的操作给我讲讲。”

再试一个自己用得上的改动，比如加个开关，打印时隐藏家访记录。每次只改一处，看看页面有什么变化，也让 Agent 指出对应改了哪些代码。

如果搜索能用了，打印却乱了，就把现象告诉 Agent，让它排查。对着一个自己正在用的功能看代码，更容易明白它在做什么。

四、复用与维护

工具做好后，换一批学生资料再试一次。查找、计算、排版的代码还在，搜索和打印功能也可以继续用。如果新资料的格式不同，再让 Agent 调整读取方式。

也可以换成自己的工作：批量改文件名、对比两份表格、做一个资料查询页面。选一个具体功能，让 Agent 帮你实现，边用边改。项目文件和使用说明一起保存好，下次就能接着做。

工具用久了，资料和要求怎么保存？让 Agent 记住要求，按需整理资料

可以先做一个自己用得上的小功能。代码看不懂的地方，就结合运行结果让 Agent 解释。

五、GitHub：借鉴项目与版本管理

想实现一个功能，可以先去 GitHub 看看有没有现成项目。读介绍、看演示，找到接近的，再让 Agent 帮忙运行和修改，也能参考其中的代码。

修改过程中，用 Git 留下可用的版本，方便对比改动、排查问题。GitHub Desktop 可以通过界面完成这些操作。需要在多台电脑间同步，或与别人一起修改时，再推送到 GitHub；只在本机使用，保存本地版本就可以。

GitHub 实践：找项目、网页 Fork、Desktop Clone，以及保存版本

六、让 Agent 调用更多工具：CLI 与 MCP

项目里不必每个功能都从头写。Agent 也可以调用已有工具，运行程序、查看改动，或读取工作软件里的资料。CLI 和 MCP 是两种常见的方式。

CLI：通过命令调用工具

CLI 就是命令行接口。比如查看项目里有哪些文件改了，可以在 GitHub Desktop 里看，也可以在终端运行 git status。有终端访问能力的 Agent，也能调用这条命令，读取结果后继续检查。

看看这个项目有哪些文件改了，再查看具体差异，帮我梳理这次改了什么。先不要提交。

同样的方式也可以用来运行脚本、处理文件。GitHub 也提供了 CLI，可以查询项目中的问题记录、查看合并请求等。工具需要先安装；涉及账号的操作，还需要登录和相应权限。

git status 说明 · GitHub CLI

MCP：连接工具和资料

MCP 是连接 AI 应用与外部工具、资料的一套协议。接入后，Agent 可以发现服务提供的功能，并按约定调用。比如连接钉钉的相关服务后，读取表格，再创建一篇整理好的文档。

用学生情况卡的资料来说，就可以让 Agent 读取钉钉里的成绩和记录，计算成绩变化，再写入家长会文档。实际能读什么、能写什么，取决于接入的服务和账号权限。

钉钉 MCP 实践：连接服务、读取表格、生成文档

CLI 和 MCP 有时能完成相同的事。同一个项目也可以配合使用：通过 MCP 读取资料，再调用命令行工具处理文件。
