刚才的情况卡里，成绩变化是怎么算出来的？可以拆成下面几步来看：

程序先找到学生的成绩，算出期末和期中的分差，再填到情况卡里。怎么算、没有记录时写什么，都可以在提需求时告诉 Agent。

再看一个例子：帮我列一份待沟通名单

老师可以直接把需要说出来：

成绩下降了，或者家长有反馈的学生，都先找出来；已经沟通过的，这次先不列入。

Agent 可以把这个要求写成筛选规则，让程序逐个检查学生的记录，列出符合条件的人。老师看过名单后，再安排沟通。

如果打开代码，可能会看到“字典”以及 or、and、not 这些写法。字典可以用来按学号查资料；后面几个词用来组合筛选条件。结合图里的例子看，会比单独记这些词更容易理解。

为什么 Agent 可能先把资料整理成表

最初给 Agent 的是几段文字。为了以后能反复查找和计算，它可以先把成绩整理成“学号、科目、期中、期末”这些固定栏目。

比如要找张三的数学期末成绩，程序先按学号和科目找到对应记录，再读取“期末”这一栏。每条成绩都按相同的栏目保存，就能用同样的办法查找。

成绩、课堂表现和家访记录里都保留学号，程序就能把同一个学生的资料对应起来，也不容易把同名学生弄混。

附带的演示文件包采用了表格文件，它里面的几个文件可以这样看：

文件 在演示文件包里的作用
三份 .csv 放资料的表格。CSV 是一种简单的表格文件，Excel 可以打开或导出
index.html 用浏览器打开的页面，这个例子的界面和处理程序都在其中
使用说明.txt 本地演示的使用说明；Agent 也可能生成 README.md 等说明文件

这个演示用了 CSV 文件。你不必事先把资料都转成 CSV，可以先把现有文件交给 Agent，让它看看怎么读取更合适。

下次为什么还能继续用

刚才完整的过程是：

你提供资料 → 程序查找、计算和排版 → 你核对 → 打印或保存 PDF

程序已经写好了查找、计算和排版的方法。下次换上新资料，按说明运行就行。生成以后，再检查成绩和记录是否正确，确认后再打印给家长。
