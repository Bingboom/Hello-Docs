# 用过以后，再看代码怎样工作

刚才我们没有手写每一行代码，但已经用到了代码的几个基本能力：

| 刚才看到的结果 | 程序做了什么 |
| --- | --- |
| 张三的成绩和记录出现在同一张卡上 | **查找：**按学号找到对应资料 |
| 提高 20 分、下降 6 分、暂无记录 | **计算和判断：**算分数差，判断升降；没有记录就显示约定文字 |
| 每个学生都有自己的情况卡 | **写入：**把结果放到新的卡片里，保留原始资料 |
| 三个人都按同样的规则处理 | **重复：**处理完一个学生，再处理下一个 |

```text
按学号查资料 → 按规则计算和判断 → 写入情况卡 → 处理下一个学生
```

这是一种常见的处理方式。你决定怎样算、缺少记录怎么办、结果放哪里，Agent 把这些做法写成程序。

### 再看一个例子：找出需要继续沟通的学生

老师可以先定一个规则：**成绩下降，或者有家长反馈，并且还没有沟通过**，就先列进待沟通清单。

Python 可以用“字典”保存按学号对应的资料，就像通讯录里按号码找联系人。找到记录后，用“或（or）”“与（and）”“非（not）”组合条件，把符合条件的学生写进清单，再处理下一个人。

同样的规则可以连续处理全班学生；下次更新资料，再运行就能得到新的清单。老师负责确定规则、核对结果，再决定怎样沟通。

### 为什么 Agent 可能先把资料整理成表

最初给 Agent 的是几段文字。为了以后能反复查找和计算，它可以先把成绩整理成“学号、科目、期中、期末”这些固定栏目。

这些栏目就像抽屉上的标签。“学号”放在这里，“科目”放在那里，程序要找“张三的数学期末成绩”，就知道该到哪里找。每条记录按同样的栏目保存，下一位学生也能照着处理。

可以把学号想成资料上的标签：成绩、课堂表现和家访记录都对应到这个标签，就能找到同一个学生。

附带的演示文件包采用了表格文件，它里面的几个文件可以这样看：

| 文件 | 在演示文件包里的作用 |
| --- | --- |
| 三份 `.csv` | 放资料的表格。CSV 是一种简单的表格文件，Excel 可以打开或导出 |
| `index.html` | 用浏览器打开的页面，这个例子的界面和处理程序都在其中 |
| `使用说明.txt` | 本地演示的使用说明；Agent 也可能生成 README.md 等说明文件 |

CSV 是这个演示采用的表格格式，是实现时作出的选择。开始提需求时，说清手头有什么资料、想得到什么结果就可以；怎样读取和整理，可以让 Agent 根据资料安排。

### 工作流程怎样留下来

刚才完整的过程是：

```text
你提供资料 → 程序查找、计算和排版 → 你核对 → 打印或保存 PDF
```

查找、计算、排版已经保留在程序里，使用方法写在说明里。下次换资料，这些步骤还能继续执行。资料选得对不对、结果能不能交给家长，仍由你确认。这就是这个项目里留下来的工作流程。
